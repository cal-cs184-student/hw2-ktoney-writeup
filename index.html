Section I: Bezier Curves and Surfaces

Part 1: Bezier curves with 1D de Casteljau subdivision

de Casteljau’s algorithm is a recursive way to create a Bezier curve using control points, making it easier to implement in code. Essentially, we start with a set of control points and linear interpolation (lerp) value t between 0 and 1. We run lerp between adjacent points. If we had n control points, we'll now have n - 1 intermediate control points. We repeat this until we have 1 final point, and this point is guaranteed to be on our curve. We repeat this for varying values of t until we get a smooth enough set of points to form a curve.

Part 3: Area-weighted vertex normals

In this part, we implemented area-weighted vertex normals. In order to find the vertex normal for a given vertex, we want to iterate over the neighboring faces/triangles of this vertex. In order to do this, we use a HalfedgeIter variable to keep track of which half edge we are at. If the current face corresponding to the half-edge is a boundary, we skip it. We then get all 3 vertices of the current face we are at, say p0, p1, and p2. We then calculate edge vectors from point p0, p1 - p0 and p2 - p0. Taking the cross product of these two vectors yields us a normal vector proportial to the area of the triangle. We add this to running sum vector of all the neighboring faces to the vertex. We then take the twin of the current halfedge and take the next halfedge to iterate to the next triangle, and repeat until we reached the same start halfedge. By the end, we have sum vector of all the neighboring area-weighted normals and return the normalized vector.
As we can see, vertex normals make the shading appear smoother, as instead of one normal for each triangle corresponding to a shade, it is a gradual shift interpolated between vertex normals.

Part 6: Loop subdivision for mesh upsampling

In order to implement loop division, we first iterate through every vertex in the current mesh using VertexIter. Then we calculate u based on the weights mentioned in lecture for old vertices, which is 3/16 if degree 3 and 3/(8n) otherwise, where 1-nu is the weight of the original vertex's position and u is the weight of its original neighbor's position. Then we take a weighted average of these vertices based on these weights, and store v's newPosition in a member variable before we update the whole mesh. We then iterate through all the edges of the original mesh, and calculate the new position of the newly genereated midpoint/vertex with a weight of 3/8 for vertices on the edge and 1/8 for vertices opposite of the edge, and store this value an edge member variable for later use. We then iterate through all the original edges again and split them, and set the positions of the new midpoints/vertices to the values we just calculated earlier. We then iterate threw every newly created edge and flip them only if they connectt and old and new vertex. Finally we finish by updating the positions of every vertex. I think a major thing that helped implement this function was making sure to use the member variables for new positions in vertices and edges, as they help make sure to not overcomplicate code by overwriting old values of vertices or making it difficult to distinguish new vertices and edges from old ones.
